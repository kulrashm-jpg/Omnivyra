## 1. Executive Summary

DESIGN-001 approved a six-context architecture: Identity, Evidence, Knowledge, Trust, Generation, Distribution. This constitution converts that architecture into enforceable law: 24 first-class objects with lifecycles, field-level production contracts for every intelligence field, a closed event vocabulary, consumer contracts, AI governance across five domains, the review model, the learning contract, versioning law, thirty platform invariants, measurable conformance criteria, and compatibility guarantees.

The constitutional test for any future change is the DESIGN-001 conformance rule, expanded: **an implementation is conformant iff it writes through the single write authority, grounds through the Grounding Authority, validates through the pipeline, uses the canonical confidence vocabulary, leaves every persisted fact explainable, and violates none of the invariants P1–P30.** The remaining unspecified layers — APIs, schemas, migrations, task breakdowns — are exactly the layers this document's constraints exclude by design: they are implementation realizations whose acceptance test is §12 plus P1–P30.

## 2. Canonical Object Model

Common law for all objects: every object is tenant-bound with referential integrity; every object answers the explainability questions appropriate to its class; no object may be mutated outside its owning context's write authority.

The 24 first-class objects: **Company** (tenant root; binds identity, domains, industry-pack selection; User + verified registry authority). **Evidence** (immutable, attributed observation; superseded never edited). **Observation** (typed extraction from Evidence; immutable; re-extraction versions). **Fact / Knowledge Node** (typed assertion with state, confidence, lineage; append-only versions, current pointer moves). **Inference** (derived Fact candidate, pending validation/review; disposition recorded). **Insight** (synthesized cross-fact interpretation; becomes a Fact on acceptance). **Recommendation / Opportunity / Risk** (actionable derived proposals with lineage; immutable + disposition). **Competitor** (entity + competes-with relationship, tier, gate scores; evidence-authoritative, user-lockable). **Audience / Goal / Strategy** (interpretive Fact families). **Campaign / Content / Marketing / Context Intelligence** (consumer-facing projections of Facts; rebuilt, never hand-edited). **Problem Transformation** (interpretive Fact family, 9 fields; user-authoritative on confirmation, inference-labeled otherwise). **Confidence** (composite trust record per Fact version; computed only). **Provenance** (source/generator/reviewer/lineage record per version; immutable). **Review** (human disposition on an Inference or contested Fact). **Conversation** (a session of the unified engine; turns are Evidence; append-only transcript). **Learning Signal** (a correction/acceptance/outcome observation feeding calibration; immutable). **Grounding Context** (the assembled, versioned input handed to any AI workflow; immutable snapshot per generation run).

Explainability requirements per class: Facts and everything derived from them MUST answer all seven explainability questions. Evidence MUST answer source/when/how-collected. Projections MUST be traceable to the Fact versions they render. Inferences MUST retain their Grounding Context reference permanently.

## 3. Canonical Field Contract Specification

**Contract law (every field):** belongs to exactly one Object and one context; orphan fields are prohibited (P18). Authority types: **Observed** (evidence-attested), **User** (user-authoritative; lock on edit), **Derived-Deterministic** (recomputed by rules; never hand-edited), **Derived-Interpretive** (AI-assisted; inference-labeled; user-confirmable to User authority). Universal source priority unless a contract overrides: **User confirmation > verified registry/external authority > website first-party claim > structured metadata > AI extraction > AI inference** — constitutionalizing the certified fill-empty/lock invariants. Overwrite policy defaults: User-authority fields never auto-overwritten (proposals only); Observed superseded by better/fresher evidence with recorded lineage; Derived recomputed. The certified anti-patterns (classifier overriding user, null-then-overwrite, phantom locks) are unconstitutional. Review default: auto-approve within safety envelope; contested or user-authority-touching values require review. Deprecation: a field is deprecated by contract amendment with a sunset in which it remains readable; silent removal is prohibited.

Full per-field contracts are specified across Identity (company_name, canonical_website, domains/logo/favicon/language/country, social_profiles), Company Facts (founded_year/team_size/revenue_range), Classification (industry/category/business_classification/business_model — Derived-Deterministic, user-overridable, weak-signal fallback carries low confidence, conflicts are contradictions not lost bands), Offering & Market (products_services, target_audience, geography, competitors), Commercial (7 fields — the certified best-governed family, mandatory server-side validation, user confirmation converts to User authority), Marketing Intelligence (7 fields — Sem-validated, evidence-grounded), Problem Transformation (9 fields — inference labeled, deterministic fallback prohibited), and Trust/system fields (confidence composite §7-computed never writable; provenance immutable; user_locked explicit; freshness; evidence links). Validation strictness and confidence ceiling follow the determinability class.

## 4. State Machine Specification

Transitions not listed are forbidden; each machine has one owning context; only the owner executes transitions. **Evidence:** Collected → Extracted → Active → {Superseded | Expired} → Archived (forbidden: edit-in-place, Archived→anything, deletion outside retention). **Fact / Knowledge:** Unknown → Inferred → Observed → Confirmed with lateral Corrected (terminal authority) and Contradicted (must resolve via Review); Proposed for generator candidates (forbidden: Confirmed/Corrected overwritten by non-user; Inferred presented as Observed; silent Contradicted-resolution). **Inference / Generation run:** Requested → Grounded → Generated → Validated → {Proposed → Accepted | Rejected} | Failed (forbidden: Generated → persisted without Validated; any transition bypassing Grounded). **Recommendation/Opportunity/Risk:** Generated → Validated → Presented → {Accepted | Dismissed | Expired} → Archived. **Conversation:** Started → Active(turns) → {Completed | Abandoned} (forbidden: direct Fact writes; re-asking a satisfied node). **Review:** Requested → Assigned → {Accepted | Rejected | Corrected} → Closed / Expired. **Learning Signal:** Captured → Aggregated → Applied → Archived (Applied only ever adjusts calibration/policy/pack, never Facts). **Confidence:** recomputed deterministically on triggers, history retained (forbidden: monotonic floors; manual override without a Review record).

## 5. Domain Event Specification

Common event law: every event carries tenant, aggregate id + version, causation/correlation ids, producer identity + version, timestamp. Events are the **only** cross-context signal — the dual notification stack certified in [A2 C11] is unconstitutional. Delivery is at-least-once; consumers MUST be idempotent (dedup on event id + aggregate version). Ordering is guaranteed per aggregate, not globally. Retry: exponential backoff with dead-letter capture; dead-letters are operator-visible. Observability: every event type emits count/latency metrics; every event is audit-retained. Payloads reference objects by id+version; they MUST NOT embed mutable state. The full catalog per context is enumerated in [`../appendices/event-catalog.md`](../appendices/event-catalog.md).

## 6. Consumer Contract Specification

Every consumer declares, and the Grounding Authority enforces: required knowledge (denied if absent → declared fallback), optional knowledge, minimum confidence per field class, freshness tolerance, refresh triggers, degradation behavior, explainability pass-through obligations. No consumer may bypass the Grounding Authority for grounding (P11); display/ops reads use projections. The twelve consumer contracts (Company Profile UI, Content, Campaigns, Strategic/Intelligent Mix, Reports, Recommendations, MarketPulse, Engagement, Analytics/Customer Success, AI Runtime, Future Agents) are specified in [`../appendices/consumer-catalog.md`](../appendices/consumer-catalog.md).

## 7. AI Governance Specification

**Prompt governance.** Prompts are versioned governed assets owned by the Generation context: registered, semantically versioned, approved before production, retired formally. Every prompt MUST declare its field targets' determinability class and carry the matching evidence-discipline clause; prompts containing internally contradictory evidence stances (the certified [A4 §4] class) fail approval. **Model governance.** Supported models are a registered set; routing is pipeline policy (plan tier, cost, capability) at the single gateway. Fallback across providers is permitted only among approved models; model changes are versioned events; rollback restores the prior routing policy version. **Grounding governance.** Grounding Contexts are versioned snapshots. Required sections: knowledge, evidence, constraints, gaps. Prohibited inputs: raw profile-row serializations, other AI outputs presented as evidence, unlabeled inference, cross-tenant data, unattributed text. **Generation governance.** Deterministic boundary: observable fields MUST use extract-or-null; deterministic logic MUST NOT fabricate content. Inference boundary: interpretive fields may infer, always labeled, never above the inference confidence ceiling. Hallucination boundary: any claim without evidence linkage in an observable field is a validation failure, not a low-confidence result. **Evaluation governance.** The offline judge harness is the standing evaluation bench: versioned datasets sampled from production lineage; acceptance criteria per workflow gate prompt/model version promotion; regression testing on every prompt/model/grounding version change is mandatory. **Safety governance.** Protected fields: all User-authority and Confirmed/Corrected Facts — AI proposals only, never writes. User authority is absolute and permanent per field until the user releases it.

## 8. Review & Approval Specification

Review types with trigger, reviewer, approval rule, confidence effect, downstream impact: **Auto-approved** (inference within safety envelope), **Needs Review** (validation soft-flags / interpretive above impact threshold / below auto floor), **User Confirmation** (proposal touches user-authority field; low-confidence queued), **Admin Review** (identity changes, cross-tenant conflicts, contradiction escalations), **Accepted/Rejected/Corrected** (terminal, immutable, reviewer-attributed; Accepted raises review-confidence, Rejected demotes generator calibration, Corrected is the highest-value Learning Signal), **Expired** (window lapse → conservative field-contract default). Dispositions are captured as Learning Signals; Review executes Knowledge transitions via callback.

## 9. Continuous Learning Specification

Inputs (all captured as Learning Signals): user edits/corrections, confirmation dispositions, suggestion accept/reject, conversation corrections and question-rephrasing signals, generated-content performance, campaign outcomes, engagement, analytics drift, review outcomes, bench-evaluation results. Outputs (the only permitted effect classes): confidence calibration, evidence-selection policy weights, industry-pack content revisions, prompt-revision triggers, question-value re-ranking. Preservation of determinism: learning adjusts *parameters of declared policies*, never behavior paths; the same inputs + the same policy versions MUST reproduce the same outputs. **Learning never silently changes Facts (P14).** Decay rules: signals age out of calibration windows per declared half-lives. Retraining/prompt-improvement triggers: correction-rate or bench-regression thresholds, breaching which opens a governance action — automatically opened, humanly decided.

## 10. Versioning Specification

Universal law: semantic versioning everywhere; MAJOR = breaking contract change, MINOR = additive, PATCH = corrective. Every versioned artifact records its lineage; rollback = re-pointing to a prior version, never destructive. Per-artifact compatibility rules are specified for Evidence (append-only), Knowledge (version chain), Grounding (schema versioned), Prompt/Model (bench-gated promotion, instant re-point rollback), Generation (run-versioned), Confidence (calculator versioned, dual-write comparison on MAJOR), Review (immutable), Projection (rebuildable at any version), Conversation (session-versioned, replay-verify dedup on engine MAJOR), Consumer contracts (N/N−1 dual-serving), and Architecture (amendments are versioned documents; the prior constitution stands until ratification).

## 11. Platform Constitution (Invariants)

The thirty invariants P1–P30 are enumerated with rationale and audit anchors in [`../appendices/invariants.md`](../appendices/invariants.md). The four singletons (P4) — one write authority, one grounding authority, one confidence vocabulary, one conversation engine — are permanent and non-waivable. Non-waivable invariants: P3, P4, P8, P11, P14, P19, P21, P30.

## 12. Architectural Conformance Rules

Measurable pass/fail criteria per compliance area, evaluated per PR and per release: Ownership (zero write paths to Knowledge outside the authority), Grounding (zero AI call sites consuming non-Grounding-Context input), Evidence (every new Fact version links ≥1 evidence id or carries inference label + grounding ref), Confidence (zero self-reported confidence keys; 100% of Fact versions carry calculator-versioned composites), Provenance (100% coverage; lineage resolves), Validation (zero persisted generation outputs without a ValidationPassed event), Lifecycle (zero forbidden state transitions), Event (all cross-context effects traceable to events), Consumer (all consumers registered), Explainability (sampled fields answer all seven questions). A release is conformant only if all areas pass; waivers require a versioned constitutional amendment. These are machine-checkable as the CI census rules (GOVERNANCE §3).

## 13. Backward Compatibility Specification

Consumer-facing projection shapes are preserved through migration; the 96 registered grounding consumers migrate by re-pointing, with contract N/N−1 dual-serving. The certified off/shadow/enforce pattern with divergence forensics is the mandatory instrument for every cutover; shadow mode MUST demonstrate zero unauthorized overwrites before enforcement. Every constitutional subsystem lands dark, byte-faithful by default, per-tenant promotable, instantly revertible. Schema evolution is additive-first; destructive changes only after consumer contract sunsets; the dual-source schema ambiguity certified in [A1 §4] is resolved by declaring a single ordered migration lineage for all new objects. No consumer may observe a behavior change without a contract version change and an event trail.

## 14. Production Readiness Certification

Every certified defect class maps to a binding instrument: 10 write authorities → P3/§12; 5 grounding mechanisms → P4/P11; unvalidated chat-save → P10/P19; confidence contract drift → P6/P12; evidence mis-routing → P22; consistency vacuum → single-graph + Con tier; no learning loop → §9; deterministic fabrication → P20; tenancy by discipline → P21; dual notification stacks → P23. See [`../appendices/traceability-matrix.md`](../appendices/traceability-matrix.md) for the full trace.

## 15–16. Final Constitution & Certification

**Production Constitution Complete.** Every object, field, lifecycle, event, consumer, and governance surface named in the scope has a binding contract. Every audit-certified defect is closed by a named invariant or contract, not by intention. Conformance is measurable (§12). The remaining unspecified layers are exactly the ones this document's constraints exclude by design — APIs, schemas, migrations, task breakdowns — and the constitution defines the acceptance test for all of them: §12 conformance plus P1–P30. No architectural decision remains open; implementation decisions remain, as intended, free within constitutional bounds. From this point forward, every implementation, code review, PR, and feature is evaluated against this constitution: conformant work realizes the specification; non-conformant work is rejected regardless of local merit (P30).
