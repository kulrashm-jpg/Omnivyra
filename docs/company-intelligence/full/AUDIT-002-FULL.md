# AUDIT-002 — Architecture Ownership & Canonical Responsibility Certification (FULL EDITION)

> **Archival Full Edition.** Maintained version: [`../architecture/AUDIT-002.md`](../architecture/AUDIT-002.md). Frozen at ratification. Corrections via [amendments](../amendments/README.md).

**Method:** two targeted read-only passes (field-level write/read ownership map; classified consumer inventory) synthesized with AUDIT-001. **Classification: Partially Owned.**

---

## 1. Canonical Source of Truth Matrix

Seven candidate "sources of truth" exist. One is canonical by decree, one by adoption, and the rest are partial authorities.

- **S1 — `company_profiles` row.** The persisted profile. No single code owner: ten write authorities. De facto ultimate authority — every other source derives from or overlays it. Canonical as *storage*; no single code owner.
- **S2 — Canonical Profile Adapter (`getCanonicalProfile`, adapter:300).** The one gated read of S1 plus a canonical-context overlay. Declared canonical read authority; flag default off → currently byte-faithful passthrough to S1 via legacy `getProfile`. Canonical **for grounding reads** (aspirational for the rest); adoption tracked by a hand-maintained static registry of 96 consumers.
- **S3 — Legacy `getProfile` (Pulse.ts:720).** The original read plus hidden autoRefine/languageRefine side effects. Residual authority — still the actual execution path even for S2 consumers while the flag is off. Superseded by decree, not by wiring.
- **S4 — Canonical Context (assimilation engine + `company_context_*`).** Deterministic firmographic fan-out. Overlay-only, fill-empty-only, dark by default. Subordinate to S1 by design.
- **S5 — Company Knowledge Graph.** "What we know" derivation + question governance. Declares itself "the ONE canonical model"; adopted by **one endpoint** (`define-target-customer`). Canonical by intent, not adoption.
- **S6 — Intelligence Context (`company_context_intelligence`).** Structured context intelligence sections. Independent parallel authority — not gated by the canonical-grounding flag, not overlaid through S2. Read directly by MarketPulse (four services) and the recommendation engine. Canonical *for its own table* but a second, ungated grounding channel.
- **S7 — Crawl metadata / knowledge versions (`report_settings.*`).** Website change state + crawl-derived facts. Authoritative for change detection — but physically embedded inside S1's contested JSONB column.

**Certification:** multiple authorities demonstrably exist. There is exactly one declared canonical read seam (S2) with a real adoption registry, but it is read-only, dark by default, and grounding-scoped. **No canonical write seam exists at all.** S5 and S6 are competing knowledge authorities with disjoint adoption.

## 2. Field Ownership Matrix

**The ten write authorities (W1–W10):** W1 `saveProfile` → `buildSavePayload` → upsert (guarded; the **only** path that adds locks); W2 AI refine `buildRefinedPayload` (guarded, **bypasses `buildSavePayload`**); W3 `bootstrapCompanyProfile` (raw, fill-empty, idempotency marker); W4 `refreshDiscoveredMetadata` (raw, lock-aware); W5 `touchProfileRefreshedAt` (raw); W6 `setup-company` creation + `onboarding/complete` (raw); W7 `guidance.ts` (raw report_settings update); W8 `saveProblemTransformationAnswers` (via W1; the **only** writer of PT confidence); W9 report_settings sub-key stores (fingerprintStore, knowledgeVersionStore, knowledgeSnapshotStore, orchestrationLedgerStore, agentStateStore, activationReadinessService — raw read-merge-write); W10 governance `company_facts`/`profile_review` merge + ops backfill script. The `define-*` endpoints write **nothing** — they return structured fields to the client, which stages them and persists through W1 (this is the launder path AUDIT-003 §7 dissects).

**Per-field certification highlights.** `website_url` is the strongest-owned field (verified domain, role-gated change, tenant uniqueness). `name`/socials/logo/facts are High. The commercial (7), marketing-intelligence (7), and problem-transformation (9) field groups are the best-governed families, with real user-lock protection. `industry`/`category`/`business_classification` are re-derived by the classifier in **both** `saveProfile` and `buildRefinedPayload`, and the classifier can overwrite the user's typed value. `competitors`/`competitors_list` are hard-coded to `null`/`[]` in `buildSavePayload` and always overwritten later in `saveProfile` (order-dependent). `report_settings` is the most contested object: W1 does a **full-object replacement**, while every sub-key store does read-merge-write — a partial `report_settings` on a save drops sibling sub-keys.

**Lock, confidence, provenance, KG coverage** were mapped per field. Notably, `field_confidence` is written by refine under keys `company_name` and `unique_value_proposition`, while the columns and the KG/provenance readers use `name`/`unique_value` — so those nodes' confidence always falls back to `'low'`. Phantom locks exist: `geography` and `social_profiles` are honored by writers but never added to `user_locked_fields` by any path.

## 3. Service Responsibility Matrix

Clear owners: identity resolution (hardened in PROD-CX-004), website resolution, crawling, crawl-refresh decision (`evaluateRefreshGate`), change detection, company facts, provenance (read-time derivation), canonical context. Conflicted or missing: AI grounding (canonical for 96 consumers but four grounding mechanisms total); industry classification (classifier vs user, no lock protection); competitors (spread over four service files + a parallel chat path); **confidence (no owner; vocabulary + key drift)**; knowledge graph (owner exists, jurisdiction doesn't); intelligence context (ungated parallel channel); recommendations (reads split canonical/legacy); and — the single largest gap — **persistence** (ten writers, two conventions, no repository layer).

## 4. Lifecycle Ownership Matrix

**L1 Website change** — mostly owned, but two disjoint notification systems (backend orchestration events vs. frontend localStorage/CustomEvent) with no owner of downstream consistency. **L2 Creation** — owned end-to-end by `setup-company` (writes raw, outside the service seam). **L3 Manual edit** — owned, but with internal precedence conflicts (classifier override, competitors null-then-recompute, report_settings full-replace). **L4 AI refinement** — a single clear orchestrator (`runProfileRefinement`) but ambiguous initiation (user refine, staleness-on-read `getProfile autoRefine`, or onboarding). **L5 Competitor update** — three entry paths, one engine spread over four files. **L6 Guided conversation** — no server-side owner of conversation state or "what was already asked" across endpoints (the gap the KG was built to fill; adopted 1/6). **L7 Bootstrap** — the cleanest lifecycle: sole owner, idempotency marker, fill-empty, no AI, no confidence writes.

## 5. Consumer Ownership Matrix

Read-path split (production): **96 canonical-seam consumers** (registry-complete for AI grounding), **~26 legacy `getProfile` modules**, **~40 raw table sites**. Content generation, campaigns/planner, Strategic/Intelligent Mix (BOLT), reports, recommendations, trends, engagement, and creator consume the whole profile as AI grounding through the canonical seam (mostly indirect via `buildContentContext`). MarketPulse (×4) and the recommendation engine additionally read `company_context_intelligence` **directly** — the ungated second channel. Analytics/customer-success/onboarding consume the confidence *numbers* (a hard ≥60 threshold in four services). AI-runtime stores use `report_settings` as storage. **The Chrome extension consumes no company-profile data** — its only `/user/profile` call is user identity, outside the domain.

## 6. Ownership Conflict Register (14 conflicts)

C1 no canonical write seam (10 writers, 2 conventions, 4 bypassing `saveProfile`). C2 four grounding authorities. C3 KG vs Canonical Context (two "single source of what we know"). C4 report_settings container (full-replace vs ≥8 read-merge writers; lost-update races). C5 competitors null-then-overwrite (order-dependent implicit contract). C6 confidence key/vocabulary drift (`company_name`/`unique_value_proposition` written; `name`/`unique_value` read — nodes permanently degrade; `'Needs Review'` band unrecognized; `business_model` mismatch). C7 classifier vs user on industry/category (re-classification inside the user save path, unprotected). C8 phantom locks (geography, social_profiles honored but never set). C9 read initiates write (autoRefine triggers the full refine lifecycle from a read call site). C10 S6 ungated (MarketPulse ×4 + recs read intelligence context outside the flag). C11 two downstream-notification systems. C12 registry-by-hand (96-entry static list; drift-prone). C13 conversation-state ownership absent across endpoints. C14 tenancy owner mismatch at the data level (no FK, non-isolating RLS, TEXT company_id; not covered by `withTenantGuard`).

## 7. Architectural Boundary Certification

Clean: Identity (best boundary), AI (single provider seam). Overlapping: Business (classifier reaches into the user-edit boundary), Marketing (two AI production paths converge), Intelligence (parallel to — not layered under — the profile boundary), **Knowledge (the most overlapped — three representations with key drift between them)**, Recommendations (crossed inconsistently), Guidance (fragmented across W7 + KG + per-endpoint loops). **Persistence: undefined boundary — nobody owns it.**

## 8. Final Ownership Certification

**Partially Owned.** Ownership quality is bimodal by axis. What is clearly owned pulls toward Mostly Owned: the AI-grounding read axis is genuinely consolidated (one seam, a complete 96-consumer registry scoped to a defensible jurisdiction, with flagged rollout machinery); the AI provider boundary, the crawl/refresh lifecycle, bootstrap, and identity/website each have exactly one competent owner; the commercial, marketing-intelligence, and problem-transformation field groups have coherent write ownership with real user-lock protection. What is not owned pulls toward Highly Fragmented: **persistence has no owner at all** — the single most consequential finding; the knowledge/confidence boundary is contested by three implementations with active silent contract drift (refine writes confidence keys the knowledge graph and provenance service cannot read); `report_settings` has ≥9 writers with formally undefined precedence; conversation/question governance has 1-of-6 jurisdiction; and tenant isolation is owned by convention, not structure. Not "Highly Fragmented" because functioning ownership institutions exist (the registry, the refresh gate, the lock system, the bootstrap contract) and the migration direction is explicit in the code's own headers. The failure mode is **incomplete jurisdiction**: the institutions that exist govern reads and AI spend, while writes, confidence, and conversation state remain ungoverned commons. The 14 conflicts (§6) and the boundary overlaps (§7) constitute the certified ownership gap inventory.
