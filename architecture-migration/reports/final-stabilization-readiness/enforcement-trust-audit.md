## Trust Findings
- Baseline file does not match the runtime tree. Enforcement fails on mixed oversized and unsafe-any drift, while duplicate-owner baseline is stale in the opposite direction and would allow regression from 0 back to 7.
- Raw and true-risk metrics are both regenerated by scripts, but enforcement compares against an older true-risk-enforcement baseline.
- The ownership scanner is AST-aware for mutation calls but only detects chained .from(...).insert/update/upsert/delete patterns. Wrapper calls and repository facades can mask ownership unless explicitly modeled.
- Duplicate-owner detection is symbol/function based. It does not prove semantic delegation, and local functions with different names can escape detection.
- Cycle detection handles import type only at import declaration level, but named type specifiers inside normal imports can still inflate runtime-cycle results.
- Unsafe propagation detection is regex/context based and counts comments, broad local typings, and UI/service utility anys as critical unless excluded by path or nearby narrowing.
- Ignored directories are limited to node_modules, .next, .git. Runtime code is not broadly hidden by skipDirs.

Verdict: enforcement is useful as a regression alarm but not authoritative until baselines are regenerated from the restored tree and scanner false-negative classes are closed.
