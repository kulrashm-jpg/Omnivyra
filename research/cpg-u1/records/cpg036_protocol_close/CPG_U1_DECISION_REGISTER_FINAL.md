## B. The four CPG-034 interpretations — full analysis

### D-A — jurisdiction balance within a class

| Aspect | Analysis |
|---|---|
| **Rule** | Round-robin across families in the fixed order `US-SEC, FR-SIRENE, BR-CNPJ, LEI-ONLY`; each family's queue in rank order; exhausted families stop contributing |
| **Alternatives** | (i) no balancing, rank across the whole class; (ii) fixed per-family quotas; (iii) allocation proportional to pool share |
| **Selection bias** | (i) lets the family with the most enumerated candidates — plausibly US-SEC — dominate held-out, so results would describe mainly one registry regime. (ii) refuses whenever one family is thin, stalling the study on the scarcest jurisdiction. (iii) makes composition depend on how hard the enumerator worked on each family, which the enumerator controls. **Round-robin** equalises contribution while pools allow and degrades gracefully. Residual bias: a thin family is under-represented, which the published realised composition makes visible |
| **Reproducibility** | Fully deterministic from frame + seed + fixed order |
| **Freeze before candidate selection?** | **Yes** — the enumerator must know that jurisdiction breadth matters, and the order must not be chosen after the frame is seen |
| **Decision** | **ADOPT** |

### D-B — contaminated companies into development

| Aspect | Analysis |
|---|---|
| **Rule (modified)** | Development filled with ineligible companies first, then eligible, capped at the **exact** quota; surplus ineligible → `DEVELOPMENT_SURPLUS` |
| **Alternatives** | (i) CPG-034: *all* ineligible into development, unbounded; (ii) rank-draw development ignoring eligibility; (iii) exclude ineligible entirely |
| **Selection bias** | Held-out is unaffected by any option, since ineligible companies can never enter it. (i) makes development size and reference workload depend on how many famous companies the enumerator lists. (ii) spends clean candidates on development, shrinking the held-out pool. (iii) discards useful development cases. Residual bias of the chosen rule: development skews toward well-known, contaminated firms, making the **pilot yield optimistic** — handled by SAFETY = 1.5 and disclosed as limitation 11 |
| **Reproducibility** | Deterministic |
| **Freeze before candidate selection?** | **Yes** |
| **Decision** | **MODIFY** (exact quota + surplus status) |

### D-C — ranking

| Aspect | Analysis |
|---|---|
| **Rule** | `sha256("<seed>\|<scheme>:<identifier>")`, identifier-string tie-break; two stage-separated seeds under commit–reveal; duplicate identifiers and domains refused |
| **Alternatives** | (i) rank on company name; (ii) platform RNG shuffle; (iii) CPG-034 rule without commit–reveal |
| **Selection bias** | (i) renaming a row re-rolls it — a covert selection lever. (ii) reproducibility depends on the RNG implementation. (iii) **a seed known before the frame is complete lets an enumerator compute ranks and choose which companies to add** — the decisive weakness, closed by commit–reveal. The duplicate checks stop one entity entering twice under two schemes to double its odds |
| **Reproducibility** | Fully reproducible from published seed + frame; SHA-256 is platform-independent |
| **Freeze before candidate selection?** | **Yes** — commitments must be published before the frame exists |
| **Decision** | **ADOPT + HARDEN** |

### D-D — "committed test fixture"

| Aspect | Analysis |
|---|---|
| **Rule (modified)** | TEST path class ∪ CPG_IMPLEMENTATION path class over `git ls-files` at the resolver SHA, plus the development-only registry |
| **Alternatives** | (i) CPG-034 test-paths-only; (ii) the whole repository; (iii) registry only |
| **Selection bias** | (i) **misses companies embedded in CPG source** — verified: Cloudflare in `grounding/acquisition/discoveredSource.ts:232`, Tesco in `grounding/entityResolution.ts:223`. (ii) the whole repo names many companies in marketing, docs and unrelated features; over-exclusion would bias held-out toward obscure firms. (iii) depends entirely on an attestation. The chosen union combines mechanical evidence where CPG was built with attested history for everything outside the repository |
| **Reproducibility** | Deterministic at a fixed SHA; the registry is hashed and append-only |
| **Freeze before candidate selection?** | **Yes** |
| **Decision** | **MODIFY** |
